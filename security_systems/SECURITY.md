# Security reporting and scope

This is a teaching reference, not a production-certified isolation layer. See
[the threat model and implementation limits](docs/TECHNICAL_NOTE.md).

Do not put an unpatched exploit, real credential, or personal record in a public
issue. Use the parent repository's GitHub private vulnerability reporting when
available. Otherwise contact its maintainer through the GitHub profile to arrange
a private channel; do not include exploit details in a public message.

The workshop uses deliberately incomplete code and synthetic secrets. Keep those
exercises local; do not connect the starter to production credentials or services.
