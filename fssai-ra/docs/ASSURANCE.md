# Assurance claims and evidence

This document is the claim boundary for release `v1.0.0`. A passing test means the
specified property held for the synthetic fixture and implementation exercised by
that test. It does not establish comprehensive security, fairness, educational
benefit, or production readiness.

Read it as a contract with the reader: every public claim this project makes
appears below with the code that enforces it, the test that exercises it, and the
thing it does **not** mean. A claim that cannot be given all three columns should
not be made.

Figures quoted here are generated by `python scripts/generate_results.py` and
checked against the paper by `tests/test_paper_alignment.py`, so prose and code
cannot drift apart silently.

## 1. Accountable action

| Public claim | Enforcement or mechanism | Executable evidence | Limit |
|---|---|---|---|
| A model may propose an action but cannot execute it | Every proposal is routed through the policy enforcement point; the model backend holds no credential and exposes no execution method | `tests/test_privilege_invariance.py`, `CF-BI-01` | A compromised enforcement service or host administrator is outside this claim |
| Approval binds to one exact proposal | Canonical proposal digest checked by the executor, covering target, transition, evidence version, and resource version | `test_target_or_arguments_changed_after_approval_are_denied`; scenario `changed_target_after_approval` | The teaching approval authority is not a production identity service |
| Approval fields are authenticated | Trusted-key HMAC verification with an explicit key allowlist | `test_tampered_approval_is_rejected_before_mutation`; `test_untrusted_approval_key_is_rejected_before_mutation` | The repository key is intentionally non-secret; it demonstrates authenticated fields, not secret management or non-repudiation |
| A genuine approval for something else is still refused | Audience, proposal digest, approver role, and expiry checked independently of the signature | Model-check variants `authentic_wrong_audience`, `authentic_other_proposal`, `authentic_wrong_role`, `authentic_expired` | Identity proofing and role assignment are outside the teaching profile |
| An application profile limits state transitions | Validated YAML profile compiled into executor checks | `test_domain_transition_rule_denies_an_approved_invalid_transition` | Profile correctness and domain legitimacy require human governance review |
| The executor limits its own authority | Independent operation allowlist, checked before anything else | `test_executor_rejects_an_approved_but_unallowlisted_operation` | A compromised executor or administrator remains outside this claim |
| A stale record requires renewed review | Expected authoritative version and starting state | `test_changed_authoritative_case_requires_renewed_review` | Concurrent distributed databases require stronger transaction design than the teaching register |
| Retrying does not duplicate the transition or its evidence | Persistent request identity, cached execution result, first-writer approval binding | `test_retry_is_idempotent_and_cross_request_reuse_is_denied`; `CF-AA-11` | External tools must provide compatible idempotency, evidence, and status lookup |
| The requester cannot approve their own proposal | Separation of duties refused at issue time by the approval authority | `test_requester_cannot_approve_own_proposal`; `CF-AA-15` | Identity administration and collusion are outside the teaching profile |
| The approver's role comes from their authenticated identity | API reads the role from the principal, never from the request body | `test_openapi_control_plane_workflow` | Requires a real identity provider in a deployment; see §6 |

### The durability claim, stated per profile

This is the claim most often overstated elsewhere, so it is split.

| Profile | Guarantee | Evidence | Limit |
|---|---|---|---|
| `single-transaction` (Postgres or SQLite) | The mutation, the execution receipt, the intent record and the outcome record commit **in one transaction**. A case that moved without a record of who moved it is unreachable. | `tests/test_atomic_execution.py::test_mutation_and_both_evidence_records_commit_together`; `test_a_failure_inside_the_transaction_leaves_no_trace` | Atomicity with a *foreign* system is impossible. An email, a payment, or a vendor student-record write still needs the outbox, an idempotency key, and reconciliation. |
| `best-effort` (Redis, or two separate stores) | An interrupted outcome is **detected**, reported as uncertain, retained, and reconciled exactly once. Never retried blindly. | `test_completed_mutation_is_marked_uncertain_then_reconciled_once`; scenario `outcome_evidence_interruption_and_recovery` | Redis is durable but not transactionally coupled to the evidence ledger. |
| `volatile` (in memory) | Teaching only. Every record is lost on restart. | — | Reported as a high-severity finding by `fssaira doctor` and on `/health`. |

The active profile is reported on `/health` and in the evaluation report, so a
reader always knows which guarantee produced a given result.

## 2. Bounded intelligence

| Public claim | Enforcement or mechanism | Executable evidence | Limit |
|---|---|---|---|
| A model cannot set its own review level | The action class is read from the capability catalogue, never from the call; an unknown capability is classed as consequential | `tests/test_privilege_invariance.py` (7 tests); scenario `model_declares_its_own_action_class` | The catalogue is deployment configuration; a compromised administrator can weaken it |
| An attempted downgrade is visible, not merely blocked | Declared and effective class both recorded on the policy decision; a counter is incremented | `test_the_attempted_downgrade_is_recorded_as_evidence` | Detection depends on someone reading the counter; see `docs/OPERATIONS.md` |
| Egress-capable tools are denied by default | Explicit egress classification and default-deny policy | `test_prompt_injection_is_stripped_and_egress_blocked` | This does not inventory every real output, telemetry, DNS, or maintenance path — see `IB-3` |
| An outward destination in arguments is also denied | Argument inspection for URLs, mail addresses, and host:port pairs on non-egress tools | Scenario `exfiltration_hidden_in_arguments` | A determined encoder can evade a regular expression; this is a cheap layer, not the control |
| A runaway agent is stopped by policy, not by its own loop | Call budget counted at the enforcement point | Scenario `runaway_agent_exhausts_call_budget` | Budgets bound one agent's calls, not overall system load |
| Routing cannot widen authority | The grant, catalogue, and enforcement point are identical whichever model is selected | `test_routing_cannot_widen_authority` | A subverted router can still select a worse model |
| Retrieved content is treated as data | Fenced, labelled envelope with fence-escape neutralisation; the enforcement point ignores retrieved text entirely when deciding | `test_a_document_cannot_close_the_fence_and_start_instructing`; `CF-BI-02` | **Prompt injection in ordinary language is not assumed to be detectable.** The load-bearing controls are downstream |
| A compromised model obtains no authorization | Least-privilege grant plus default-deny policy, evaluated against a deliberately hostile backend | Scenario `compromised_model_against_least_privilege` | Demonstrates containment of this fixture's behaviour, not of all model behaviour |
| Inference stays inside the boundary by default | Ollama is the default backend; a non-local endpoint produces a configuration warning; fallback can be refused | `test_a_non_local_endpoint_is_reported_as_a_sovereignty_warning`; `test_fallback_can_be_refused` | The architecture will not stop you using a hosted API; it stops you doing so silently |

## 3. Import boundary and directionality

| Public claim | Enforcement or mechanism | Executable evidence | Limit |
|---|---|---|---|
| Unauthenticated or malformed artifacts are quarantined | Type, size, envelope-size, and source-signature checks before the channel | Five `import_rejects_*` scenarios; `tests/test_import_api.py` | HMAC authenticates the *channel*, not the truth of the content; a compromised but correctly-keyed publisher still gets through |
| The inward channel offers no return path | No read, reply, or acknowledgement method; enforced by `assert_no_return_path` inspection | `test_neither_end_exposes_a_return_path`; `test_a_channel_that_can_read_back_is_rejected`; `CF-IB-01` | Software topology is not physical directionality |
| A real unidirectional transport exists, not only a class shape | UDP sender with the read side shut down; receiver that never transmits; per-frame hash and HMAC; redundancy instead of retransmission | `tests/test_diode_transport.py` (9 tests, over a real loopback socket) | Loopback is not an air gap. A certified diode governs the physical link |
| A diode claim requires an interface inventory | Declared interfaces with a named control and owner each; outward-capable paths enumerated | `test_the_interface_inventory_names_every_path_a_claim_depends_on`; `test_an_interface_without_an_owner_is_flagged` | The reference inventory is a template; an institution must complete its own |
| A bad-signature artifact is quarantined | Trusted-source key check at import | `test_compromised_update_is_quarantined_and_no_self_escalation` | The demo uses a shared-secret digest, not production artifact signing |
| Active content is stripped | Marker list plus inline URL and script removal | Scenario `injection_specimen_stripped_at_import` | **Removes mechanical injection only.** Nothing downstream relies on it |

## 4. Evidence, data, and transport

| Public claim | Enforcement or mechanism | Executable evidence | Limit |
|---|---|---|---|
| Altering a past evidence record is detectable | Hash-linked records; `verify()` recomputes the chain | `test_insider_record_tampering_is_detected`; `CF-AA-02` | A privileged writer can truncate an uncheckpointed history; see `XC-3` |
| Agents cannot write their own record | Appends require a credential held only by the evidence service | Scenario `agent_cannot_write_its_own_record`; `CF-AA-01` | Where available, enforce append-only by database grant: `fssaira db ddl --role <role>` |
| Truncation is detectable, not only alteration | Independent Spark job recomputes hashes **and** checks for sequence gaps | `jobs/verify_evidence_chain.py` | Requires the archive to be running; not exercised by the offline suite |
| Poisoned data can be rolled back | Lineage record per job plus versioned snapshots with content manifests | Scenario `poisoned_data_rolled_back_to_approved_snapshot`; `CF-RD-01` | Retention must protect the pinned snapshots; see `RD-2` |
| A manifest identifies the exact data a decision used | Content hash bound to the decision through the approval's evidence version | `CF-RD-02` | A manifest identifies data; it cannot restore data that has been deleted |
| Event ordering and replay are available | Monotonic offsets, idempotent producer, read-from-offset | `CF-ET-01`, `CF-ET-02` | **Delivery is at-least-once.** Consumers must be idempotent; a log is transport, not the system of record |

## 5. Machine-checked assurance

This section is what release `v1.0.0` adds, and the claims are about *method*
rather than about any individual control.

| Public claim | Enforcement or mechanism | Executable evidence | Limit |
|---|---|---|---|
| The profile's declared authority space contains no violation | Bounded model checker enumerates 240 configurations and runs the real executor against each, checking 5 invariants | `tests/test_verification_and_conformance.py`; `evaluation/results/v1.0.0-verification.json` | **Bounded**, not a proof. Unbounded versions, arbitrary identities, concurrent interleavings, and infrastructure behaviour are out of scope and are stated in the report's own `bounds` field |
| Every denial control is actually reached | 11 distinct denial codes each produced by at least one configuration | `test_every_denial_control_is_actually_reached` | Reaching a control is not the same as proving it correct |
| The checker would notice a permissive executor | Negative control: a deliberately over-permissive reference predicate produces violations | `test_the_checker_catches_an_executor_that_is_too_permissive` | Confirms the checker is not vacuous; does not bound its sensitivity |
| Every declared control is load-bearing | 8 controls ablated one at a time; all 8 restored their harm; authority coverage 1.0 | `test_every_declared_control_is_load_bearing` | Ablation shows a control matters in *these* scenarios, not that it is sufficient |
| The properties survive component replacement | 25-check portable conformance suite run against the configured backends on 2 independent profiles | `test_the_reference_memory_bundle_conforms`; `test_the_transactional_sql_bundle_conforms` | Behavioural conformance for these fixtures. **Not a penetration test, an audit, or a certification** |
| Every conformance check names the claim it defends | Each check cites a control-contract requirement id, verified against the contract | `test_every_conformance_check_maps_to_a_contract_requirement` | A citation is traceability, not proof of adequacy |
| Legitimate work still completes | 6 benign tasks, false-denial rate 0.0, reported beside the containment rate | `test_evaluation_reports_utility_beside_containment` | A small benign suite. It shows the system is not trivially over-restrictive, not that it is usable at scale |
| The paper cannot drift from the code | Generated figures; the paper and the deck are parsed and checked against them | `tests/test_paper_alignment.py` (29 tests) | Checks numbers and required limit statements, not the correctness of the argument |

## What is not evidenced

- resistance to a shared host administrator, a compromised signing authority, or
  colluding control owners;
- physical one-way transfer, or a complete interface inventory for any real site;
- stochastic prompt-injection rates for a named model and configuration;
- completed Spark/Iceberg analytics-profile conformance, retention testing, or a
  real local-model benchmark;
- policy-service outages or process crashes around a real external side effect;
- concurrent and distributed failure modes: the model checker is single-threaded
  and the suite is single-process;
- reviewer accuracy, workload, appeal quality, fairness, accessibility, cost, or
  energy;
- institutional deployment, independent audit, penetration test, or certification.

These are planned evaluation areas. New evidence should be versioned with its test
inputs, environment, denominators, results, failures, and exclusions.

## Reproduction record

For a result intended for citation, record the repository commit, Python and
dependency versions, operating system, command, test count, and complete output.
Retain raw outputs before writing a narrative summary. Use a release tag rather
than an unversioned branch URL when comparing results across institutions.

```bash
python scripts/generate_results.py          # regenerate every figure
python scripts/generate_results.py --check  # confirm the committed results still hold
pytest                                      # the full deterministic suite
```
