## Trusted computing base

| Component | Trusted | Why | Property | Failure mode |
|---|---|---|---|---|
| Execution mediator (AccountableExecutor + register credential) | yes | only path to a governed write | R1 | compromise allows unapproved writes; approvals are Ed25519 so it still cannot mint them |
| Context gate + privacy pipeline | yes | only holder of the decrypt credential | R2 | compromise discloses whatever custody lets it decrypt |
| Key custody | yes | holds KEKs and wrapped DEKs | encryption, erasure | compromise decrypts everything; independent key backups outside custody defeat erasure |
| Approval service (Ed25519 private key) and review queue | yes | creates authority | R1 | compromise mints approvals; executor cannot tell |
| Grant authority and delegation exchange | yes | creates entitlement | R2 | compromise mints grants |
| Evidence notary key | yes | attests history | tamper evidence | compromise can sign rewritten history unless checkpoints are published externally |
| Model registry publisher key and serving runtime digest report | yes | decides which model is which | attestation | a runtime that lies about its loaded weights defeats digest checks (no TEE quote) |
| Kernel floor validator and domain-pack review | yes | gates policy changes | pack cannot weaken kernel | a bypassed loader admits a weakened pack |
| Models, agents, router, retrieval, tools | no | treated as adversarial in every test | none relied on | can propose, request, and lie; F18 shows it gains nothing |
| Domain pack authors | no | floor-checked | none relied on | can declare bad but at-floor policy; the floor is not a wisdom check |
